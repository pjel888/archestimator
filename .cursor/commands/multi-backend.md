# Portable Backend Workflow Adapter

Follow `AGENTS.md`, relevant `.ai/00_system` provider/data/security protocols,
the Validation Matrix, and
`.ai/08_prompts/000_Planning Prompts/Multi-Agent-Execution-Directive.md`.

- Ground the task in current routes, repositories, schemas, bindings, trust
  boundaries, failure paths, authorization, and acceptance criteria.
- Select exploration, debugging, implementation, dependency, security, or review
  capability classes through `.ai/12_agents/codex-role-model-matrix.json`; never
  assign authority by provider brand or a hardcoded model.
- Parallelize independent analysis only. Assign one writer/integrator for shared
  code, migrations, D1/R2/DO/queue state, Git state, or external resources.
- Use native, thread, emulated, or single-agent mode with the same contracts and
  capability fallback chain.
- Run the cheapest decisive authorized evidence. Product tests/builds require
  `TEST_TASK`; external writes and destructive actions require their exact
  authority boundary.
- Preserve partial evidence and shared-worktree changes; report exact files,
  commands/results, proof limits, recovery, and remaining risk.
