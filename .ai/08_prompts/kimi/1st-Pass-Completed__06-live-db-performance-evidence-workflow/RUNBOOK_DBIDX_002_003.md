# Runbook: DBIDX-002 / DBIDX-003 — Live Performance Evidence Workflow

## Purpose

This runbook turns the repo-static query/index inventories (`DBIDX-001`) into a safe, repeatable workflow for collecting live or staging evidence before proposing indexes or RPC rewrites.

## Scope

- **DBIDX-002** — Collect linked/staging database parity and row-count evidence for candidate indexes.
- **DBIDX-003** — Collect EXPLAIN plans, RLS cost, and hosted route timing before RPC/query rewrites.

## Non-goals

- Do not create `CREATE INDEX` or `CREATE OR REPLACE FUNCTION` migrations from static evidence alone.
- Do not run against production without explicit owner authorization and a maintenance window.
- Do not print secrets or database URLs in reports.

## Prerequisites

| Target | Required tooling | Required access |
| --- | --- | --- |
| Repo-static | `bun` | None |
| Linked Supabase staging | `bun`, `supabase` CLI linked to a project | Read-only database role |
| Local Postgres | `bun`, `psql`, local Postgres 15+ | Connection string with read-only or owner role on a seeded copy |

## Quick start

```bash
# 1. Repo-static evidence only (default, no credentials)
bun run perf:collect-live-evidence -- --mode=static

# 2. Generate live SQL for a linked Supabase project (does not execute)
bun run perf:collect-live-evidence -- --mode=linked

# 3. Execute live SQL against a linked Supabase project
bun run perf:collect-live-evidence -- --mode=linked --run-sql

# 4. Execute live SQL against a local Postgres instance
DATABASE_URL="postgresql://..." bun run perf:collect-live-evidence -- --mode=local --run-sql
```

## What the orchestrator does

1. Runs `scripts/build-performance-query-inventory.ts` to produce a per-route query inventory.
2. Runs `scripts/audit-dbidx-repo.ts` to produce a migration-derived index inventory.
3. For live modes, generates `live-evidence.sql` containing read-only queries for:
   - Table row counts (`pg_stat_user_tables.n_live_tup`)
   - Table sizes
   - Index usage (`pg_stat_user_indexes`)
   - Unindexed foreign-key columns
   - Top statements by total/mean time (`pg_stat_statements`)
4. If `--run-sql` is set and prerequisites are met, executes the SQL and stores raw output as `live-evidence-raw.json`.
5. Writes `evidence-report.md` with a clear proof-boundary label and migration guardrail.

## Evidence artifacts

| Artifact | Source | Proof boundary |
| --- | --- | --- |
| `query-inventory.md` | Repo scan | repo-static |
| `query-index-audit.md` | Migration scan | repo-static |
| `live-evidence.sql` | Generated template | manual-proof-pending |
| `live-evidence-raw.json` | Executed SQL | linked-provider or local-only |
| `evidence-report.md` | Orchestrator | strongest proven boundary above |

## Go/no-go gates before index/RPC proposals

| Gate | Required evidence | Acceptable proof boundary |
| --- | --- | --- |
| Candidate index exists in repo scan | `query-index-audit.md` | repo-static |
| Query is hot and table is large | `live-evidence-raw.json` row counts + `pg_stat_statements` | linked-provider or local-only |
| Query plan shows sequential scan or high cost | EXPLAIN output on representative data | linked-provider or local-only |
| RLS policy cost is acceptable | EXPLAIN (ANALYZE, BUFFERS) with `set local role authenticated` | local-only or linked-provider |
| Hosted route timing is acceptable | Vercel Speed Insights or Playwright route transition metrics | browser-proven or hosted-provider |

## Decision matrix

| Evidence state | Safe next action |
| --- | --- |
| Only repo-static inventories exist | Document findings; **do not create migrations**. Re-run in linked/local mode. |
| Linked/local evidence exists but no EXPLAIN | Generate EXPLAIN plans for the top queries before proposing indexes. |
| EXPLAIN shows clear sequential scan on large table | Draft a candidate index; test on staging copy first. |
| RLS cost dominates plan | Revisit RLS policy or consider security-invoker RPC with measured proof. |
| Route timing is still poor after index | Investigate application-level N+1, caching, or payload size. |

## Adding new queries to EXPLAIN

1. Copy the query from `query-inventory.md` into a new `.sql` file.
2. Replace any dynamic values with representative constants.
3. Prefix with `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`.
4. Run via `supabase db query --linked --file <file>` or `psql $DATABASE_URL -f <file>`.
5. Attach the JSON plan to the task folder's `EVIDENCE.md`.

## Safety checklist

- [ ] No `CREATE INDEX` or `CREATE OR REPLACE FUNCTION` statements are generated by the orchestrator.
- [ ] Secrets are not printed in logs or reports.
- [ ] Live SQL is read-only (SELECT against system/catalog views).
- [ ] Production runs require explicit owner authorization.
- [ ] Evidence report labels the proof boundary correctly.

## Common blockers

| Blocker | Recovery |
| --- | --- |
| `supabase` CLI not linked | Run `supabase link --project-ref ebxxqidacheyapmmzavr` in a staging context, or use `--mode local`. |
| `DATABASE_URL` missing | Export a connection string to a seeded local/staging database. |
| `pg_stat_statements` not enabled | Run `CREATE EXTENSION IF NOT EXISTS pg_stat_statements;` on the target (requires elevated privileges). |
| Docker/local Supabase is down | Use `--mode local` with a standalone Postgres, or generate `live-evidence.sql` for manual execution. |
