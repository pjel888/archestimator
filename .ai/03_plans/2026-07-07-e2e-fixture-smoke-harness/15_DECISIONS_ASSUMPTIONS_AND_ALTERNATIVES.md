# 15 — Decisions, Assumptions, and Alternatives

## Architectural decisions (load-bearing)

### D-1 — Dev-auth-cookie bypass is the primary smoke auth path
- **Problem.** Smoke needs deterministic auth without email/Google.
- **Constraints.** localhost-only; no inbox; no real OAuth account; CI must be hermetic.
- **Options.** (a) dev-auth cookie (existing pattern); (b) magic-link automation; (c) Google OAuth automation; (d) `PLAYWRIGHT_STORAGE_STATE` generated by a manual login.
- **Advantages (a).** already used by every authed spec; localhost-scoped; deterministic; no external dependency.
- **Disadvantages (a).** requires a seeded D1 profile (solved by FR-SEED1); bypass is dev-only (must not ship to prod).
- **Rejected (b):** non-deterministic (email latency), slow, needs mailbox access. **(c):** needs a seeded Google account + secrets in CI, brittle, Google TOS-sensitive. **(d):** no generator exists; a one-time manual login doesn't reseed cleanly across machines; stale session.
- **Recommendation.** (a) primary; (d) documented as the production-staging opt-in path (OPEN-1).
- **Conditions that would change it.** owner requires real-session smoke against hosted preview ⇒ implement (d) as a Phase 9 follow-up.

### D-2 — webServer stays `bun run dev`; local-isolated preview D1/R2
- **Problem.** Where does smoke get its D1/R2?
- **Options.** (a) local preview via OpenNext `getCloudflareContext`; (b) remote D1 seeding; (c) miniflare/`vitest-pool-workers`; (d) test-only Worker deploy.
- **Chosen (a).** OpenNext already bridges `next dev` to local bindings (evidence: `getCloudflareContext` usage across `src/lib/`). Smallest change surface.
- **Rejected (b):** shared state, flake, pollutes real data, violates isolation. **(c):** large change, out of smoke scope, different runtime than prod. **(d):** heavier than needed.
- **Conditions that would change it.** T0.1 falsifies ASSUMP-1/2 ⇒ escalate to (c) or (d).

### D-3 — Smoke = routing/interaction/data, not visual regression
- **Problem.** Scope of assertions.
- **Chosen.** prove the flow works end-to-end via DOM/route assertions.
- **Rejected.** broad visual matrix (poor cost/value for closed beta; owned by existing visual specs).

### D-4 — Explicit env-gated skip (umbrella + sub-flags)
- **Chosen.** `ARCHESTIMATOR_E2E_SMOKE=1` + per-flow sub-flags; every skip names the missing flag.
- **Rejected.** silent omission (current ad-hoc pattern is hard to reason about); single binary flag (no incremental CI opt-in).

### D-5 — retries:1 on CI + 2-strike quarantine
- **Chosen.** balance flake tolerance vs signal.
- **Rejected.** retries:0 (too noisy); retries:2+ (hides real flakes); delete flakes (loses signal).

### D-6 — Seed is script-based, local-only, idempotent — NOT a migration
- **Chosen.** `scripts/e2e/seed-local.ts` + `sql/*.sql`, `--local` only, sentinel-scoped.
- **Rejected.** a `migrations/` seed (would pollute remote `ARCH_DB` when applied; not resettable per-run; shared across envs).

### DEC-terms — (pending T0.3) terms-gate seed vs UI accept
- **Decision owner.** executor after T0.3 read. Recommended: Option A (seed terms-accepted) for determinism + a secondary UI-accept test.
