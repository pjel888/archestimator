## Trust order (Cloudflare Workers)

Cloudflare Workers run behind the Cloudflare edge. Header trust is ordered:

| Order | Header | Trust | Use |
|---|---|---|---|
| 1 | `CF-Connecting-IP` | **TRUSTED** — set by Cloudflare edge, cannot be spoofed by client | Canonical client IP for rate-limiting, audit, security |
| 2 | `True-Client-IP` | TRUSTED only if Cloudflare enterprise + Argo Tiered Caching enabled; otherwise treat as untrusted | Do not use by default |
| 3 | `X-Forwarded-For` | **UNTRUSTED** — client-settable; never use as canonical | Reject for security decisions |
| 4 | `X-Real-IP` | UNTRUSTED — client-settable | Reject |

**Policy**: derive client IP exclusively from `CF-Connecting-IP`. If absent, the request did not come through Cloudflare edge; treat as dev/preview/internal and use explicit dev-mode handling (below).

**Rule**: never use `request.headers.get('X-Forwarded-For')` for any security decision. If a caller persists identity material, it must derive an HMAC separately; `deriveClientIdentity()` intentionally does not write or persist raw IP data.

## IPv6 aggregation

Raw IPv6 addresses (`2001:db8::1`) MUST be aggregated for any persistence or coarse audit:

- **Persistence**: store HMAC of raw IP (sensitive pseudonymous)
- **Coarse audit / rate-limit prefix**: `/48` prefix (e.g., `2001:db8::/48`)
- **Never** store raw IPv6 in logs, audit tables, or rate-limit keys unless owner-accepted security exception

For IPv4: `/24` prefix for coarse audit; HMAC for persistence.

## Dev / localhost / preview handling

| Context | Detection | Handling |
|---|---|---|
| Localhost dev (`bun run dev`) | `env.DEV_AUTH_BYPASS === '1'` + `localhost` host | Allow with `isDev: true` flag; rate-limits use canonical `127.0.0.1`; audit logs marked dev |
| Cloudflare preview (`*.workers.dev`) | URL host ends with `.workers.dev` | Allow with `isPreview: true`; rate-limits use canonical `0.0.0.0` placeholder; audit logs marked preview |
| Production (custom domain) | `archestimator.com` host | Full policy applies |
| Direct Worker invocation (no edge) | `CF-Connecting-IP` absent AND not dev/preview | **Fail-closed**: deny request |

**Never** fall through to `X-Forwarded-For` when `CF-Connecting-IP` is missing in production.

## Rate-limit key derivation

Per-surface rate-limit keys compose:

| Surface class | Key composition | Example |
|---|---|---|
| Public share (anonymous) | `share:ip:<ipHash>` + `:share_token_hash` | `share:ip:abc123:def456` |
| Public share password attempt | `share:pwd:<ipHash>:<share_token_hash>` (P10 lockout) | `share:pwd:abc123:def456` |
| Invite accept | `invite:<ipHash>:<invite_token_hash>` | `invite:abc123:def456` |
| AI ask | `ai:ask:<userId>` (authenticated) | `ai:ask:user-xyz` |
| AI package-builder | `ai:pkg:<userId>` (authenticated) | `ai:pkg:user-xyz` |
| Estimate action | `est:act:<userId>:<estimateId>` (authenticated) | `est:act:user-xyz:est-abc` |
| Auth sign-in / magic-link | `auth:<ipHash>:<emailHash>` (Better Auth built-in) | deferred to Better Auth |

**Rule**: authenticated rate-limits use `userId` (stable); anonymous rate-limits use `ipHash` (HMAC, not raw IP).

## Persistence rule

**Raw IP** is NEVER persisted in:
- D1 audit tables (`account_security_events`, `ai_action_runs`, `collaboration_audit_events`, etc.)
- Workers Observability logs
- Traces
- Error envelopes

**What may be persisted**:
- `ipHash` (HMAC with server pepper, `ARCHESTIMATOR_RATE_LIMIT_HASH_PEPPER`)
- `ipPrefix` (aggregated, `/24` IPv4 or `/48` IPv6)
- `country` (derived from `CF-IPCountry` — coarse, not personal data)

## Cross-surface consistency

All touched routes and actions MUST use `deriveClientIdentity()` once and propagate the result. No surface reads headers directly.

Wave 2 source baseline introduces the helper; Wave 3 (PH-3) refactors share/invite routes to consume it.

## Adversarial test scenarios (required for Wave 2)

| Scenario | Expected behavior |
|---|---|
| Request with `CF-Connecting-IP: 1.2.3.4` and spoofed `X-Forwarded-For: 9.9.9.9` | `ip` derived from `1.2.3.4` only; spoofed header ignored |
| Request with no `CF-Connecting-IP` to production host | Fail-closed (403 or 401 as appropriate) |
| Request with no `CF-Connecting-IP` to `*.workers.dev` | `isPreview: true`, allowed with placeholder IP |
| Request with no `CF-Connecting-IP` and `DEV_AUTH_BYPASS=1` to localhost | `isDev: true`, allowed |
| IPv6 client `2001:db8:abcd:ef01::1` | `ipPrefix = 2001:db8:abcd::/48`; raw IP never logged |
| 1000 requests from same `/24` IPv4 | All map to same `ipPrefix`; rate-limit counter shared per-surface |
| Concurrent requests with same `userId` from different IPs | Authenticated rate-limit uses `userId` only; IP-independent |
| Persistence scan: grep for raw IPv4 / IPv6 in D1 audit tables | Zero raw IP rows |
