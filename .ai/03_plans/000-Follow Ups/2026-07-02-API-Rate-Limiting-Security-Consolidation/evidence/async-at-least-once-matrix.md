## Required test scenarios (per surface)

For each at-least-once surface, the following adversarial tests must exist or be added:

| Scenario | Expected behavior | Test shape |
|---|---|---|
| Duplicate message delivery | Side effect occurs exactly once; second delivery is no-op or returns prior committed result | inject same message twice; assert single side effect |
| Partial-success then retry | First attempt commits D1 but throws before R2 write; retry must detect prior commit and complete R2 without re-inserting D1 | inject failure between D1 commit and R2 write |
| Poison message (always fails) | After `max_retries`, message lands in DLQ; operator alert fires | inject always-failing message; assert DLQ receipt |
| Backoff verification | Retries follow capped exponential backoff with jitter | time-based assertion (flaky — keep bounded) |
| Cross-batch duplicate | Same idempotency key across two batches; second batch returns prior result | batch boundary test |
| Provider outage during side effect | Cloudflare Email / R2 / D1 transient failure; retry completes when provider returns | mock provider flakiness |
