## Authority And Status Vocabulary

This matrix is the current feature inventory for this pack. It supersedes narrower completion language in artifacts `01` through `08` when the documents disagree.

| Status | Meaning |
| --- | --- |
| `SOURCE_PRESENT` | Current source contains the action and its persistence path; this is not browser, hosted, or release proof. |
| `FIX_PRESENT_UNVERIFIED` | A current uncommitted change addresses a reported defect, but this planning pass did not run product tests or browser QA. |
| `KNOWN_GAP` | Current source or recent runtime evidence exposes an unresolved contract, UX, parity, or integrity issue. |
| `SECONDARY_BOUNDARY` | The action affects the Estimate Sheet but its full product lifecycle belongs to an adjacent surface. |
| `UNSUPPORTED_BY_DESIGN` | The generic component can support the behavior, but this Estimate Sheet surface deliberately does not expose it. |
| `NOT_EVALUATED` | Source may exist, but the required local D1, browser, hosted Cloudflare, or public-route evidence was not collected in this pass. |

## Cross-Cutting Invariants

Every action below must preserve these invariants unless its row explicitly states otherwise:

1. `workspace_id`, `project_id`, `estimate_id`, active tab, and selected node scope are authorized server-side; client IDs are never sufficient authority.
2. A row keeps a stable row identity across ordinary edits, variant selection, replace, move, and component localization; duplicate creates a fresh row identity.
3. `estimate_row_items.source_snapshot_json` is always a valid JSON object and never `NULL`.
4. Every persisted row mutation uses the expected row revision or equivalent stale-write guard, emits history where the action contract requires it, and returns authoritative state.
5. Component-level edits fan out only inside the owning Library or Project component scope; variant edits fan out only to rows selecting that stable variant ID.
6. Row-owned quantity, contingency, adjustment, miscellaneous cost, designation, discipline, placement, and selection remain row-owned unless the action explicitly replaces the row graph.
7. Tree and row moves are atomic with respect to destination validity, sort order, history, and visible rollback.
8. Archive preserves existing references; permanent delete follows an explicit impact contract and cannot silently convert a required snapshot to `NULL`.
9. Private D1 IDs, source snapshots, attachment metadata, and private R2 broker paths never cross into an issued/public projection.
10. A source-level implementation is not considered working until the required evidence column is satisfied for the intended environment.

## Inventory Completeness Rule

An implementer who adds, removes, renames, or changes the persistence semantics of an Estimate Sheet action must update:

1. the matching `L-*`, `C-*`, `R-*`, or `S-*` row, including cross-cutting `S-16`/`S-17` when interaction styling or render scope changes;
2. `10-DATA-INTEGRITY-BUG-AND-READINESS-AUDIT.md` when risk or proof changes;
3. `TRACEABILITY.md` when a requirement or criterion changes; and
4. `plan-pack.json` before claiming a new readiness state.

The matrix is complete for the currently discoverable route controls and code paths. It is not evidence that those actions all work in a browser, against local D1, or against hosted Cloudflare.
