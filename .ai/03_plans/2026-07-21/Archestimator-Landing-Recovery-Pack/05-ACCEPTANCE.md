# Acceptance Criteria

The redesign is accepted only when all of the following are true.

## Structure

- [ ] Four main narrative sections or fewer, plus footer.
- [ ] No capability matrix, status rail, FAQ band, proof matrix, or repeated product-playback component.
- [ ] Full desktop page height at 1440 × 900 is no more than 4,200px.
- [ ] Full mobile page height at 390 × 844 is no more than 5,000px.

## Message

- [ ] A first-time visitor can answer what Archestimator is from the first viewport.
- [ ] The hero contains one H1, one short lead, one CTA, and no feature list.
- [ ] Visible copy before the footer is no more than 260 words.
- [ ] The page communicates one connected workflow rather than an inventory of capabilities.
- [ ] No fabricated proof, customer language, metrics, AI, automation, or accuracy claims.

## Visual experience

- [ ] The primary visual is an abstract product metaphor, not a fake product screenshot.
- [ ] The scene clearly communicates estimate → proposal → review → revision.
- [ ] Signal orange is used for connection, source, review, change, and action—not decoration.
- [ ] The visitor encounters no long blank sticky regions or repeated full-screen chapters.
- [ ] Motion remains meaningful when scrubbed slowly, quickly, or in reverse.

## Accessibility and fallback

- [ ] All essential meaning exists in semantic DOM text.
- [ ] Canvas is decorative and hidden from assistive technology.
- [ ] Reduced motion presents an immediate, readable settled state.
- [ ] WebGL failure leaves a deliberate poster rather than an empty area.
- [ ] Mobile does not depend on the desktop WebGL scene.
- [ ] Keyboard focus and contrast pass existing project standards.

## Performance

- [ ] Hero copy and CTA render before the scene bundle.
- [ ] Canvas is dynamically imported.
- [ ] Scene pauses offscreen and while the tab is hidden.
- [ ] No continuous render loop after the scene settles.
- [ ] No textures, models, post-processing, physics, or particles.
- [ ] Bundle and route measurements are recorded before cutover.

## Founder review question

Do not ask whether every product truth is represented. Ask:

> Does the page make the connected estimate idea feel obvious, useful, and memorable within the first three scrolls?
