## Purpose

This is the canonical consolidated Admin plan pack. It combines the predecessor's control-plane foundations with the Founder Homebase product hierarchy and replaces the two-plan arrangement with one requirement map, one implementation DAG, one ledger, and one manifest.

## Binding consolidation results

- Current Admin defects, identity semantics, privileged-action safety, User 360, notification durability, support, flags, audit, privacy, retention, migrations, overlaps, and provider-proof boundaries are retained.
- Founder Home, search, Action Inbox, customer success, broader Entity 360, support/signals, releases, data quality, cost/capacity, analytics, and founder cadence define the product priority.
- Financial readiness, traffic/acquisition, provider integration health, error/log reconciliation, and privacy-request operations are explicit inside the existing F6/F8 units; no billing or observability backend is invented.
- One-time targeted communications remain in the core roadmap; recurrence, generalized campaign scale, optional providers, and AI remain conditional.
- Existing domain repositories remain canonical mutation owners.
- New schema is vertical-slice-only; generic workflow, dashboard-builder, CRM, and provider-copy abstractions are rejected.
- Every acceptance criterion defaults to `test_requirement: NOT_REQUIRED`; tests, builds-as-gates, browser automation, and broad QA require an explicit current-task user authorization.
