## Route Handler error envelope (RFC 9457 Problem Details)

**Canonical shape** (per `DEC-IMP-2` — RFC 9457-compatible local equivalent):

```typescript
type ArchestimatorProblem = {
  type: `urn:archestimator:problem:${string}`;   // stable, machine-readable
  title: string;                                  // short human-readable
  status: number;                                 // HTTP status (4xx / 5xx)
  detail?: string;                                // safe-context human-readable (NO stack, SQL, token, prompt, object-key, tenant-existence leak)
  code: string;                                   // stable external machine code (e.g., "share_token_expired", "rate_limited", "idempotency_conflict")
  instance?: string;                              // request-scoped path or route name (no raw params)
  requestId?: string;                             // per-request UUID (rotated per request)
  correlationId?: string;                         // optional cross-system trace (separate from idempotency key)
  retryAfter?: number;                            // seconds, present only when applicable (429, 503)
  fieldErrors?: Array<{ field: string; code: string; message: string }>; // validation only
};
```

**Forbidden in any error response** (per `RISK-P1-10`):
- Stack traces
- SQL or D1 query text
- Raw tokens (share token, invite token, OAuth token, session cookie)
- AI prompts or outputs
- R2 object keys
- Tenant/workspace/user existence disclosures that enable enumeration
- Provider response bodies
- Internal hostnames, paths, or port numbers

**`Content-Type: application/problem+json`** for HTTP 4xx/5xx Route Handler responses.

**HTTP status mapping (stable)**:

| Status | When | Code prefix |
|---|---|---|
| 400 | malformed input | `bad_request.*` |
| 401 | unauthenticated (Better Auth session missing) | `unauthenticated.*` |
| 403 | authenticated but unauthorized (workspace/project membership fail) | `forbidden.*` |
| 404 | resource not found OR token invalid/expired (NON-ENUMERATING — same response for both) | `not_found.*` |
| 405 | method not allowed | `method_not_allowed.*` |
| 409 | idempotency-key conflict, lost-update conflict, duplicate-submit conflict | `conflict.*` |
| 412 | `If-Match` precondition failed | `precondition_failed.*` |
| 422 | semantic validation failure (schema valid but business rule rejects) | `validation.*` |
| 429 | rate-limited | `rate_limited.*` |
| 500 | unexpected server error (NO internal detail leakage) | `internal.*` |
| 502 | upstream/provider error | `upstream.*` |
| 503 | maintenance / degraded | `unavailable.*` |

## Server Action error envelope (ActionResult mapping)

Server Actions continue using the existing `ActionResult` pattern (per `DEC-IMP-2`), but each touched action must define stable external codes aligned to the Route Handler codes above.

```typescript
type ActionResult<T> =
  | { ok: true; data: T }
  | { ok: false; code: string; message: string; fieldErrors?: Array<{ field: string; code: string; message: string }>; correlationId?: string; retryAfter?: number };
```

**`code`** values must match the Route Handler code prefix scheme (`bad_request.*`, `forbidden.*`, etc.) so the client treats them uniformly.

**No raw exception messages in `message`** — only safe-context user-facing copy.

## Rate-limit response (429 + Retry-After)

**Canonical 429 shape**:

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/problem+json
Retry-After: <seconds>           ; REQUIRED when delay known; integer seconds, capped at 3600
Cache-Control: no-store, private  ; REQUIRED
```

```json
{
  "type": "urn:archestimator:problem:rate_limited",
  "title": "Too many requests",
  "status": 429,
  "detail": "Please try again later.",
  "code": "rate_limited.surface",
  "retryAfter": 30,
  "requestId": "<uuid>"
}
```

**Draft `RateLimit` header fields** (`RateLimit`, `RateLimit-Policy`, `RateLimit-Reset`): DEFERRED per `DEC-IMP-1` and `OPEN-004`. Not emitted in first slice.

**Cache posture for 429**: `Cache-Control: no-store, private` — never cached.

**Non-enumerating rule**: rate-limit responses for token-bearing routes MUST NOT distinguish between "token exists but rate-limited" and "token does not exist". Both return identical envelope (`code: rate_limited.surface` or `not_found.surface` indistinguishable to caller).

## Cache posture classes

| Class | Applicable surfaces | Cache-Control |
|---|---|---|
| `no-store-private` | Auth, share/invite session, AI, upload, security errors, rate-limits, anything token-bearing | `no-store, private` |
| `no-store-public` | Health check, error sink responses | `no-store, public` |
| `private-finite-ttl` | Export endpoints (xlsx), authenticated activity feed | `private, max-age=<finite>` |
| `public-short-ttl` | Health, static manifest | `public, max-age=<30>` |
| `cache-conditional-304` | Public share read (GET) where revocation must invalidate quickly | `no-store, private` for first-slice; PH-7+ may add conditional 304 with revocation token |

**Conditional 304 + auth/revocation rule** (deferred — label per surface): for any cache-bearing public share response, the revocation signal MUST be checked before 304 returns. First-slice: no conditional 304 on token-bearing surfaces.

## Trace, correlation, request, and idempotency identifier separation

**Distinct identifiers** (per plan Section 10 API Contract Defaults):

| Identifier | Purpose | Lifetime | Format | Carried in | Logged? |
|---|---|---|---|---|---|
| `requestId` | Per-Worker-request correlation | one request | UUIDv4 | response header `X-Request-Id`, body field | yes (operational) |
| `correlationId` | Cross-system trace (Worker → D1 → DO → Queue → provider) | request subtree | UUIDv4 or W3C Trace Context `traceparent` | propagated internally; surfaced in error envelope when relevant | yes (operational, in traces) |
| `rayId` | Cloudflare edge identifier | request | Cloudflare-assigned | response header `cf-ray`, body field | yes (operational) |
| `mutationCorrelationId` | Domain-level mutation identifier (estimate action, publication publish) | mutation lifetime (24h+) | server-generated UUIDv4 stored in D1 audit table | surfaced in ActionResult; propagated to side effects | yes (audit) |
| `idempotencyKey` | Client-supplied duplicate-submit suppression key | per-key TTL (default 24h) | client-generated opaque string | `Idempotency-Key` header (Route Handler) or ActionResult field (Server Action) | hashed only (`key_hash`) |

**RULE**: never collapse `idempotencyKey` into `correlationId` or vice versa. Correlation is observability only; idempotency requires scoped persisted uniqueness. Reusing correlation as idempotency is forbidden.

**W3C Trace Context** (`traceparent`, `tracestate` headers): propagated through Worker subrequests if/when distributed tracing is enabled. First-slice: not required; surfaces that span Worker → DO must propagate `correlationId` manually.

## Redaction rules (apply before any log/metric/trace emission)

| Field class | Redaction |
|---|---|
| Raw tokens (share, invite, OAuth, session, magic-link) | hash with server pepper; never log raw |
| Passwords (share password, account password) | never log; constant-time compare only |
| Raw IP | store HMAC or /24 (IPv4) / /48 (IPv6) prefix; never log full IP unless owner-accepted security exception |
| AI prompts / outputs | never log raw; redact to length + hash if audit needed |
| R2 object keys | redact to bucket + prefix class; never full key |
| D1 SQL / query text | never log; log only query name (e.g., `share_repository.fetch_by_token`) |
| Stack traces | internal-only; never in client response |
| Email addresses | mask to `u***@domain`; redact full unless owner-accepted |

## Validation order (apply consistently across routes + actions)

```
1. Auth check (Better Auth session OR public token validation)
2. Authorization predicate (workspace/project membership)
3. Input validation (schema, types)
4. Idempotency check (if mutation; consult ledger or natural uniqueness)
5. Lost-update check (If-Match / expected revision / natural uniqueness)
6. Rate-limit check (per surface)
7. Side-effect commit (transactional)
8. Audit emission (after commit, with redaction)
9. Response (cache headers, error envelope, identifiers)
```

Steps 1–2 fail-closed: never reveal which step failed via distinguishable responses on token-bearing surfaces.
