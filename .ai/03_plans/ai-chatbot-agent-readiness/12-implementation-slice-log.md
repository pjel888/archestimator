## Implemented package-builder Draft/Apply slice

**Date:** 2026-05-28
**Scope:** first write-capable Ask Flip package-builder implementation after the package-builder readiness addendum.

- New server route `/api/ai/package-builder` supports `draft` and `apply` modes without changing the existing `/api/ai/ask` Ask route.
- `src/lib/ai/package-builder/*` now owns feature flags, schemas, provider-neutral provider contracts, DeepSeek structured-draft adapter support, authenticated read tools, deterministic draft assembly, and confirmed Apply orchestration.
- Draft mode accepts package-building prompts such as "Assemble me a 3 bedroom package, budget is 5 million pesos", uses compact authenticated project/component/template/prior-row summaries when Supabase workspace auth is available, may ask DeepSeek for structured draft hints through the provider boundary, and falls back to deterministic server-side package assembly when the provider is unavailable or invalid. The deterministic fallback now recognizes 3-bedroom condo/unit prompts, names the draft "3 Bedroom Condo Unit", creates bedroom plus toilet/bath Area Nodes, folds bounded matched template area names into the draft structure, can reuse matched workspace library components for repeated needs such as beds and wardrobes in bedrooms plus water closets and lavatories in toilet/bath areas, can use matched prior estimate rows from accessible workspace projects as reviewed allowance precedents when live library components are missing, can use bounded matched estimate-template row previews as review-required allowance rows without enabling template-source row Apply, and can build current-route matched template-insert drafts for whole reusable-template copies into existing estimates. Draft read searches use a bounded package vocabulary so generic condo prompts can discover bedroom, wardrobe, kitchen, water-closet, lavatory/basin/sink/faucet, and finish-related app data before deterministic scoring.
- Draft mode writes no production records. It returns a normalized package brief, project/estimate draft, Group/Area estimate tree draft, component/template match summaries, clearly marked allowance rows, budget summary, assumptions, warnings, operation eligibility, a server draft hash, and a server-signed HMAC draft token bound to draft id/hash, user, workspace, provider/model, and expiry. Package-builder read tools now read the workspace display context from the already server-derived `userContext.workspaceId` and must not call workspace bootstrap helpers that can create/update workspace or profile records during Draft. Linked component rows with a price option require the confirmed price-option `updated_at`; linked rows without a price option carry a component-version snapshot, and Apply rejects stale or missing freshness evidence before writing.
- Apply mode is command-style and confirmation gated. The server revalidates authenticated user/workspace ownership, rejects model/browser supplied workspace/user ids, validates the draft hash, validates estimate hierarchy and Area-only row targets, revalidates linked component items/price options against the current workspace, records a metadata-only `ai_action_runs` authorization row after signed-token and confirmation checks, and uses an idempotency key to avoid duplicate package creation on replay.
- Confirmed Apply currently creates a project, estimate shell, estimate tree nodes, and approved row items through the authenticated transactional `public.create_project_estimate_package_with_history` RPC and the `ai_package_apply_commands` idempotency table. The RPC derives the actor from `auth.uid()`, requires the same workspace editor authority as normal project creation, and rejects direct authenticated calls without the matching server-recorded authorization row; the normal production Apply writes use the user-scoped Supabase server client, with service role limited to the established metadata-only audit authorization write.
- The Apply RPC writes an `estimate_sheet_events` `ai_package_applied` event and metadata-only AI audit rows with safe summaries, created ids, source tables, tool calls, and package run correlation in the same recoverable database transaction.
- The linked Supabase remote was updated with the AI audit foundation migration `20260523144932_ai_audit_foundation.sql` and the package Apply RPC migration `20260528003000_ai_package_builder_apply_rpc.sql`; both were applied through `supabase db query --linked --file ...` and repaired into linked migration history because `supabase db push --linked` is blocked by intentional historical migration divergence. The package Apply RPC was later hardened from service-only execution to authenticated execution with DB-side `auth.uid()` actor derivation.
- Ask Flip UI now detects package-builder prompts, shows a reviewable package draft preview with tree/room plan, matched components, allowance rows, budget summary, assumptions/warnings, and requires an explicit confirmation checkbox before calling Apply. After Apply succeeds, it renders an explicit `Open estimate` link using the server-returned `projectId` and `selectedNodeId`, falling back to the project estimates list when no selected node is returned.
- Feature flags are environment-driven: `AI_PACKAGE_BUILDER_READ_TOOLS_ENABLED`, `AI_PACKAGE_BUILDER_DRAFT_ENABLED`, `AI_PACKAGE_BUILDER_APPLY_SHELL_ENABLED`, `AI_PACKAGE_BUILDER_APPLY_TREE_ENABLED`, `AI_PACKAGE_BUILDER_APPLY_ROWS_ENABLED`, and `AI_PACKAGE_BUILDER_MEMORY_ENABLED`.
- Memory/RAG remains disabled by default. A narrow package-builder memory slice is implemented behind `AI_PACKAGE_BUILDER_MEMORY_ENABLED`: accepted Apply and rejected feedback can record safe structured source signals for scoped library items/templates, read tools summarize those user/workspace-scoped signals, and deterministic Draft uses them only as ranking hints. Memory writes are best-effort, do not block feedback or Apply, do not authorize reads/writes, do not bypass freshness checks, and are not sent to the provider. The local migration `20260528103341_ai_package_builder_memory.sql` defines the memory table/RLS surface but has not been applied to the linked Supabase remote in this slice.
- Historical estimate rows are bounded, audited, provider-minimized, and used only as precedent hints. They do not become linked supplier-priced rows; deterministic Draft emits them as review-required allowance rows with historical-precedent warnings unless a current library component match is available.
- Comparable prior estimate packages are bounded, audited, provider-minimized, and used only as room/row/cost/source-coverage pattern hints. They can add matched prior-estimate area names to the Draft room program and emit reviewed allowance rows from comparable row previews, but they do not become linked supplier-priced rows or bypass Apply validation.
- Current-route row-update prompts now have a bounded first refinement contract. Package-builder read tools keep raw row ids and row revisions server-side, deterministic Draft can emit `update_existing_row` operations for matched current estimate rows, and Apply calls the existing authenticated `update_estimate_row_item_with_history` RPC for quantity, Misc Cost, and contingency changes with expected row revision protection. Ask Flip previews those drafts as row changes with patch summaries and reports updated-row counts after Apply.
- Current-route row-replacement prompts now have a scoped library replacement contract. Deterministic Draft can emit `replace_existing_row` operations for matched current estimate rows and matched scoped library components; Apply calls the existing authenticated `replace_estimate_row_item_with_history` RPC with expected row revision protection, active library/component freshness validation, deterministic correlation ids, and replacement counts in the Apply result.
- Current-route row-delete prompts now have a bounded delete contract. Deterministic Draft can emit `delete_existing_row` operations for matched current estimate rows; Apply calls the existing authenticated `delete_estimate_row_item_with_history` RPC with expected row revision protection, deterministic correlation ids, and deleted-row counts in the Apply result.
- Current-route direct template row-copy prompts now have a bounded copy contract. Deterministic Draft can emit `copy_template_row` operations for matched reusable-template row previews and existing estimate Area Nodes; Apply calls the existing authenticated `insert_estimate_row_item_with_history` RPC with copied template-row snapshot metadata and deterministic correlation ids.
- Current-route reusable-template insertion now has an end-to-end contract for prompts such as "Insert the 3 Bedroom Condo Starter template into this estimate." Draft emits `insert_template` operations only for a matched workspace template and an existing estimate Group Node target; Apply calls `insert_estimate_template_into_estimate_with_history` with deterministic correlation ids, reports inserted template node/row counts, and keeps project/estimate creation forbidden.
- Component-library creation now has a bounded Draft/Apply contract for prompts such as "Add a component to my library called Queen bed frame, category Furniture, unit set, cost 18000 pesos from Bedroom Supplier." Draft emits `create_library_component` intent and `componentCreateDraft` records only; validation rejects project/estimate/tree/row/template operations in that intent. Apply verifies the same signed draft/hash/confirmation/auth boundary, then calls the authenticated `create_ai_package_library_components_with_history` RPC. That RPC requires a matching route-recorded Apply authorization row, records/replays the component-only Apply through `ai_package_apply_commands`, rejects same-key/different-hash reuse, and transactionally calls `create_cost_library_component` with server-derived workspace/user ids, Ask Flip metadata, and one default price option. Ask Flip UI routes library-component create prompts to package-builder Draft, renders a `Library components` preview, keeps Apply disabled until explicit confirmation, and links to `/workshop/library` after successful component creation.

## Implemented read-only account-aware Ask context

**Date:** 2026-05-28
**Scope:** ordinary Ask Flip questions that need authenticated account/workspace facts without mutating records.

- `/api/ai/ask` now calls `src/lib/ai/read-context.ts` after real Supabase workspace authentication succeeds.
- The read context derives the workspace server-side, uses the user-scoped Supabase server client, and reads only selected fields needed by the detected Ask intent.
- Ask provider context includes exact `projectCount` only for project-count questions, bounded project labels for project-list questions, compact ID-free component-library matches with active price-option unit/cost/currency values for component/library/price questions, compact ID-free reusable-template matches with bounded area names and row previews for template questions, compact ID-free historical estimate-row matches for prior-row/other-project usage questions, compact ID-free project chart bucket summaries for chart/cost-breakdown questions, validated current-route project and estimate labels for route-context questions, compact current-estimate tree/row/total context for current estimate questions, compact current-estimate activity summaries for activity/history/who-edited questions, and explicit guidance that retrieved text is untrusted data.
- Ask no longer tells authenticated workspace users it cannot see scoped app data when server-derived read context is present; project-count questions should be answered from `projects.projectCount`, project-list questions should use `projects.list`, component-library questions should use `componentLibrary.matches` without inventing unavailable items, suppliers, brands, or prices, reusable-template questions should use `templateLibrary.matches` without inventing template areas, row previews, costs, or availability, historical row questions should use `historicalRows.matches` without inventing prior usage, project chart questions should use `projectCharts` without inventing buckets/totals, current-estimate activity questions should use `activityHistory.events` without inventing event actors/timestamps/changes, and current-estimate questions should use `currentEstimate` without inventing rows, areas, totals, or sheet contents.
- The server does not hardcode the natural-language project answer. It derives user/workspace, fetches compact context through app-owned reads, and lets the provider answer from that context while the server keeps authorization, minimization, and audit control.
- Normal Ask remains read-only. It must not create, edit, apply, save, or mutate records.
- Local admin DB bypass remains rejected before AI context resolution. Local dev auth bypass is rejected before AI provider calls so account-aware Ask/package-builder flows must use a real Supabase workspace session.
- Ask audit metadata now records `server_scoped_read_context` provider-send category and metadata-only `ai_data_access_events` with source tables, row counts, filter hashes, and safe summaries for Ask reads.

- compact authenticated project chart summaries for chart/cost-breakdown questions, including project/estimate labels, totals, row counts, currency code, and top space/category/supplier buckets, but no raw project/estimate/node/row/category/supplier ids;
- compact authenticated current-estimate activity summaries for activity/history/who-edited questions, including event type/label, timestamp, display actor label, target label, summary, changed fields, and total delta, but no raw event ids, actor ids/emails, project/estimate/node/row ids, correlation ids, snapshots, payload, or metadata;
- validated current project/estimate labels from the active route;
- compact current-estimate tree/row/total context from the active estimate route, including Area/Group names, paths, row counts, materials, quantities, units, unit costs, totals, and source type, but no raw project/estimate/node/row/library ids;
- compact, authenticated package-builder read-tool summaries for bounded portfolio project labels, current project estimate summaries, provider-safe current-route project/estimate/area/row context, component-library matches, template matches including bounded template area names and scrubbed row previews, and prior estimate-row precedent summaries without raw row/project/estimate ids in provider context.

Not allowed in this slice:

- raw uploaded specs/documents;
- client PII beyond the visible project display name;
- supplier private terms;
- service-role data;
- hidden prompts;
- workspace/member lists;
- raw estimate row dumps;
- raw activity exports, snapshots, payload, metadata, actor ids, actor emails, or correlation ids;
- raw component-library dumps;
- raw template-library dumps;
- any server-derived authorization ids as model authority.

Browser-provided route context is serialized as untrusted JSON and must never become authorization input.
