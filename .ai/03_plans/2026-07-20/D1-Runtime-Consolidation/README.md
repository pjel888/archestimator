## Dependency notes

- **UNIT-002 and UNIT-003 both depend on UNIT-001** (the shared module must
  exist before callers migrate).
- UNIT-002 and UNIT-003 are independent of each other and can run in either
  order after UNIT-001, but in practice doing UNIT-002 first (it touches the
  same files that have the helper copies) keeps the diff coherent.
- **Pack D depends on this pack.** Pack D's `MutationIntent` extraction composes
  these primitives; do not start Pack D until UNIT-001 and UNIT-002 are VERIFIED.
- This pack does NOT depend on Pack A or Pack B. It can run in parallel with
  Pack A (different files entirely).

## Findings considered and rejected

- **`formatPeso` deduplication (8 files)** — out of scope; it is a formatting
  helper, not a D1 runtime primitive. A separate small cleanup can do it.
- **Adding request-scoped tracing to the D1 runtime** — future work this pack
  *enables*. Adding it now would expand scope and risk; do it as a follow-up
  once the consolidation lands.
- **Migrating `ai/package-builder/apply.ts` helpers in UNIT-002** — deliberately
  deferred to Pack D, which rewrites that file's write path anyway. Migrating it
  here then rewriting it there is wasted effort.
