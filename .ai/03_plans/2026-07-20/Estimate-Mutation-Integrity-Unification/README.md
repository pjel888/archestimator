## Findings considered and rejected

- **Merging the four write paths into one** — rejected. Each fork has a reason
  (atomic multi-table batches, idempotent replay). Sharing the *rules* via
  primitives is the right shape; merging the batch composition would break
  idempotency.
- **A new `EstimateMutationService` class hierarchy** — over-engineered for
  alpha. Composable functions building `{sql, values}` arrays are the right
  grain; a class hierarchy adds ceremony without value.
- **Rewriting `EstimateSheetContent.tsx` as part of this pack** — separate
  direction option; the God-component decomposition is its own (optional) effort
  that builds on the characterization harness from Pack B UNIT-001.
- **Adding a generic "mutation logger" middleware** — out of scope. The
  primitives emit history events (the existing audit surface); a separate
  logger is a future observability addition.
