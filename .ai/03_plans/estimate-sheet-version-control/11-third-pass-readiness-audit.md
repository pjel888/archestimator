# 11 Third-Pass Readiness Audit

**Date:** 2026-05-24
**Scope:** Planning-pack refinement only. No application code, migration, generated Supabase types, or tests were implemented in this pass.

## Code-Cross-Referenced Corrections

### UX Assumptions

- Corrected the false row-action assumption. `EstimateRowItemsTable` uses a 30px action column with plain Drag, Expand, and Delete `Button` icons, not `ContextMenu`, `ActionMenuGroup`, or `ContextActionMenuContent`.
- Changed v1 row history entry point to the existing Expand icon slot. Fourth-pass review clarified that the icon is currently inert and the row details/history panel is new work.
- Documented that `EstimateSheetHeader` is a private local function inside `EstimateSheetContent.tsx`, not an importable shared component.
- Added the row-density constraint to the readiness gate: no fourth icon and no new grid column unless a visual pass approves it.

### Existing Version Metadata

- Replaced the second-pass `Rev 01` default with `V1`/`V2` compatibility labels plus editable version titles.
- Documented that the estimate route and proposal export route already derive `versionLabel` from `estimate.metadata`.
- Required named version creation to update `estimates.metadata.versionNumber`, `versionLabel`, and `latestEstimateSheetVersionId`.
- Clarified that `sheet_code` remains the estimate sheet identifier and must not be confused with per-estimate version sequence numbers.

### Snapshot And Restore Contract

- Added an explicit flat snapshot schema with `estimate`, `nodes`, `rows`, `totals`, and `schemaVersion`.
- Required row snapshots to include `source_snapshot`, row `metadata`, `discipline`, `designation`, and `link_state`.
- Tied `source_snapshot` to the existing `getSourceSnapshot()` helper contract and row `metadata` to `getEstimateRowMetadata()`.
- Required restore-as-copy to mirror `duplicateEstimateSheet()`: create estimate, remap nodes parent-first, then insert rows with remapped node ids and fresh row ids.

### Missing Events And Write Boundaries

- Added `tree_reordered` for `reorderEstimateTreeNodes()`.
- Added `estimate_metadata_changed` for `updateEstimateDetails()`.
- Added `sheet_code_regenerated` for `regenerateEstimateSheetCode()`.
- Added `node_deleted_with_children` / cascade handling for `deleteEstimateNode()`.
- Required `link_state` changes to appear in `changed_fields` and row snapshots for scalar/replacement events.

### Operational Gaps

- Defined `event_source` values: `user`, `system`, `backfill`, `template`, `restore`, `import`, and `api`.
- Defined `correlation_id` usage: server-generated by default, reused for multi-event actions.
- Added cursor pagination for event logs using `(created_at, id)` with a first-page size of 50.
- Added cache invalidation placement: RPCs stay atomic SQL; server actions call `revalidatePath()` only after RPC success.
- Added scalar edit latency benchmarking and snapshot-size guardrails.
- Added concurrent edit tests and stable event ordering expectations.

## Revised Readiness Assessment

Planning completeness is now approximately **78/100**.

The third pass fixes the biggest correctness problems from the critique, but the pack should not be handed to an implementation agent as "ready" until the remaining gates are cleared. The biggest remaining risk is not architecture; it is execution precision around row UX, RPC latency, and snapshot fidelity.

## Remaining Blockers

1. Product acceptance is needed for using the existing Expand icon slot as the row-history entry point and building a new row details/history panel behind it.
2. Product acceptance is needed for `V1`/`V2` compatibility labels plus separate editable version titles.
3. Exact implementation symbol impact must be rerun immediately before code edits.
4. The Supabase migration and RPCs do not exist yet.
5. RPC latency and snapshot-size benchmarks are planned but not measured.
6. Live RPC atomicity and concurrent edit tests need implementation-harness proof.

## Third-Pass Verdict

The first-pass architecture remains valid: append-only events plus named full-sheet snapshots. The second-pass RPC atomicity improvements remain valid. The third pass materially changes the handoff details: row UI must not be built on a non-existent menu pattern, named versions must reconcile with existing metadata readers, and restore snapshots must be flat/restorable data rather than an ambiguous tree projection.
