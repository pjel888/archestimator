- `package.json` exposes `bun run test` for `tests/unit`, `bun run test:dom` for all Vitest jsdom suites, `bun run test:e2e` for Playwright, plus targeted proof/readiness scripts for Supabase, hosted auth/export/share links, project charts, notifications, route performance, support, legal, and Vercel readiness.

## Existing Red/Unknown Notes With Evidence

- Broad `bun run validate` is currently not a reliable green signal. The FAST PATH records it as red due to charts `set-state-in-effect`, `ProposalExportPreviewDialog` design-lint, and an all-DOM phase that can hang. A later launch-readiness entry refines the red set to `useLiquidGlassRefraction.ts:118,122`, `projects-page-client.tsx:691`, `MainSidebar.tsx:370`, `lint:design` anti-patterns, and a `test:dom` hang phase.
- `tests/vitest/workspace-repository-project-list.test.ts` is explicitly called out in current-state as red for pre-existing workspace repository text expectations unrelated to dashboard work.
- Full DOM runs have a documented stability/performance risk. Current-state says full `bun run validate` can pass earlier phases but hang silently in all-DOM; `vitest.config.ts` also documents heavy jsdom component suites running serially and sometimes exceeding 15s late in a long run.
- Provider/local database proof is uneven by feature. Current-state records multiple local Supabase/Docker or linked credential blockers, including local lint/reset unavailable and linked DB credential failures. This means DOM/source-contract green does not always equal provider reality for RLS, migrations, or RPC behavior.
- Publication/share has the strongest targeted evidence, including archived shared-link verification with route/page/action/security/public-repository tests, type-check, and smoke scripts passing. Remaining GA-level risks are more operational than DOM-level: live alert/drain proof and deferred security/optimization review.
- Proposal export has focused model/workbook/route coverage, but the broad design-lint red on `ProposalExportPreviewDialog` means UX audit should inspect the preview surface directly rather than relying on tests alone.
- Charts/location/maps have broad contracts and visual/provider entries in state, but chart lint reds and provider/key/environment dependencies mean UX audit should include both static chart semantics and real map fallback/provider behavior.
- AI/package-builder has extensive deterministic tests, but because AI is documented as deferred/roadmap-only, UX audit should not infer launch-readiness from test volume. Tests prove boundaries and draft mechanics more than human trust in generated estimates.

## UX/Logistical Issues Existing Tests Likely Catch

- Redirect/caching/security regressions around auth, share links, and hosted export routes.
- Broken component rendering for many core controls, tabs, trees, modals, buttons, dropdowns, and estimate-sheet interactions.
- Contract drift in Supabase schema/RPC expectations where migrations and typed contracts are represented in tests.
- Accessibility basics in selected areas: charts, library tabs, estimate column resize, share estimate tree panel, collaboration color contrast, modal focus behavior.
- Data projection mistakes: project totals, chart aggregation, estimate tree projection, publication snapshots, proposal workbook grouping, project-source/component-library relationships.

## UX/Logistical Issues Existing Tests Likely Do Not Catch Reliably

- Authenticated browser reality across the full closed-beta flow when storage state, beta fixtures, or provider credentials are absent.
- Visual polish regressions in dense dashboard/estimate/proposal surfaces, especially spacing, hierarchy, overflow, responsive behavior, and perceived loading sequence.
- Actual provider reliability and cost/logistical issues: Google Maps key/billing/quota failure, Resend inbox delivery, Vercel analytics consent posture, Supabase linked migration drift, monitoring alert delivery.
- Multi-user collaboration confusion: stale presence, role clarity, invitation email comprehension, reconnect behavior under real network conditions.
- Real Excel/Numbers compatibility and stakeholder readability of exported proposal workbooks.
- AI answer quality, hallucination risk, user trust, or whether beta users understand that AI is deferred/experimental.

Recommended UX audit focus: use the automated suite as a contract map, not as a substitute for real user-story proof. Prioritize browser-backed stories for closed-beta auth, project dashboard, estimate sheet editing, shared-link recipient flow, proposal export preview/workbook, map fallback, and notifications/feedback/legal gates. Keep provider-dependent proof separate from jsdom/source-contract tests so audit findings can distinguish local UI gaps from operational readiness gaps.
