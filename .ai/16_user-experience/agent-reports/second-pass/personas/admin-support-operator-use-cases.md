# Admin, Support, And Operator Persona Use-Case Second Pass

Date: 2026-06-22

## Outcome

The canonical CSV has real coverage for beta allowlist admin, feedback review, release announcements, legal pages, and operations, but it compresses several distinct operator personas into broad rows. The biggest underrepresented personas are: support triager after first status update, release announcement campaign operator, legal/privacy/DSAR operator, monitoring/incident operator, provider readiness operator, and launch checklist owner. These should become separate canonical rows or structured sub-rows so beta operations are testable and assignable.

No canonical files were modified.

## Changes To Existing CSV Rows

1. `OPS-001`: correct route from `/api/resend/webhook` to `/api/webhooks/resend`; the source route is `src/app/api/webhooks/resend/route.ts:18-50`.
2. `OPS-001`: split "Operator" into at least `Monitoring / incident operator`, `Provider readiness operator`, and `Launch operations owner`; otherwise acceptance criteria cannot be assigned or proven.
3. `FEEDBACK-002`: change primary actor from `Support or platform admin` to `Support triager / platform admin`, then add acceptance criteria for pagination/search and response ownership, not just status transitions.
4. `NOTIF-002`: keep the user-facing modal row, but add a separate campaign-operator row because current evidence proves rendering/safe CTA consumption, not authoring/scheduling/targeting.
5. `PUBSITE-003`: keep public legal pages as visitor/beta-user row, but add a legal/privacy operator row for DSAR/deletion/export request handling and legal approval readiness.
6. `ADMIN-001`: keep allowlist CRUD/filter row, but add a beta-program operations row for cohorts, invite waves, accepted/revoked counts, and repair workflow.

## Acceptance Criteria Shape For Added Rows

- Monitoring operator row passes when all support monitoring proof flags and owner labels are recorded, and the report explicitly states what it cannot prove.
- Provider readiness row passes when hosted health, Vercel env presence, Resend env/DNS/webhook readiness, Supabase linked readiness, and support DNS outputs are attached or marked not run.
- Legal/privacy operator row passes when deletion/export/privacy request intake path, retention exception language, owner/legal reviewer labels, approval date, and approval reference are recorded.
- Support triager row passes when feedback can be filtered, paged/searched beyond latest 50, status changed, and a follow-up owner/response state is visible or documented.
- Release campaign operator row passes when campaign content can be previewed, safe CTA validation is enforced before delivery, and target/delivery evidence is recorded.
- Beta program operator row passes when allowlist rows can be grouped or reviewed by cohort/source/status and accepted/revoked counts are visible or exportable.
