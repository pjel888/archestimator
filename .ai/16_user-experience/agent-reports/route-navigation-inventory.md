## Coverage notes and uncertainty
- No repository-level `src/middleware.ts` was found for direct middleware routing/mutating behavior in user code; auth/redirect gates are implemented inside `src/app/workshop/layout.tsx` and route handlers.
- Route groups observed are functional-folder based (`/workshop/*`, `/workshop/projects/*`, `/workshop/library/*`, `/workshop/settings/*`, `/invite/[token]`, `/share/[token]`); no dedicated parent route-group folders like `(authenticated)` were present.
- Loading/error/not-found coverage is strongest in workshop + share routes; several public/auth routes do not define explicit error/loading wrappers and rely on inherited defaults.
- Several redirects exist for compatibility (`/workshop/components`, `/workshop/templates`, `/workshop/charts`) to preserve older URLs.
- Uncertainty: exact role/permission model for some routes is inferred from auth/token handlers and shell access checks, not from a single centralized policy file; deeper authorization policy claims should be validated against API-level checks before final role taxonomy.
