## Coverage notes and uncertainty
- High-confidence story coverage is strongest for auth/beta terms and notifications because dedicated unit tests assert parser validation, action shape, and user-facing routing.
- Onboarding and workspace bootstrap behavior has partial coverage and includes branch-heavy fixtures; some edge-cases (all failure modes around invitation/workspace integrity) are only indirectly covered.
- Some admin surfaces (settings modal navigation tree and support copy nuances) are implementation-first and should be further validated with focused UI integration tests for end-to-end discoverability.
- Notification surface currently validated through hook/action/component suites; there is optional expensive RLS proof suite (`ARCHESTIMATOR_NOTIFICATION_RLS_PROOF=1`) for live DB verification.
