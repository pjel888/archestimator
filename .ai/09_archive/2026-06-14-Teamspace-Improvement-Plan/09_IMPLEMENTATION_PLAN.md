## Phase 1 — Track A: Security prerequisites (must land before greater presence visibility)
- **T1.1 [FE] Scope project-presence payload.** In `use-project-presence.ts:79–88`, ship `{ userId, online_at, activeSurface }` only — **remove raw `activeRoute`, `activeEstimateId`, `activeTabId`, `focusedCell`** from the project channel (move fine-grained fields to the `estimate:{id}` channel). Add a route-to-surface mapper with an allowlisted enum so no exact pathname leaks. Failing test: a fake-channel project-viewer scenario captures the exact `track()` payload and asserts no raw path or sheet fields exist in type or runtime payload. Fixes `05` HIGH leak. Rollback: revert payload shape.
- **T1.2 [FE/BE] Sender-bound realtime identity.** Add a short-lived server-signed sender envelope for cursor/presence-detail events, binding `auth.uid`, channel topic, allowed realtime role, issued-at/expiry, and a key id. Receivers verify signature + topic + expiry + `payload.userId === envelope.sub` before rendering; then resolve label + color from the server roster by `userId`, ignore `payload.displayName`, drop unknown users, and escape fallback text. Failing tests: member B claiming member A renders nothing; an expired/wrong-topic/bad-signature envelope renders nothing; an unknown `userId` renders nothing; a `<script>` displayName is ignored/escaped. If the signed-envelope path proves too costly, document and implement the fallback as server-mediated Broadcast via Supabase REST/database APIs with explicit latency/capacity measurements. Fixes `05` HIGH spoof/XSS and must land before viewer cursor policy can ever be relaxed.
- **T1.3 [infra] Server-side realtime rate limit.** Set `realtime.max_events_per_second` on the project (owner-authorized). Document the value. Proof: config screenshot / API read. Pairs with the client throttle.
- **T1.4 [DB] Atomic owner/manager guards.** BEFORE DELETE/UPDATE triggers raising if a write would leave 0 `workspace_members` owners **or** 0 `project_members` access managers/owners for a project. The project trigger closes the concurrent read-then-write gap in `updateProjectCollaboratorRole`/`removeProjectCollaborator`. Prove on the PG17 harness: delete/demote-last raises, delete/demote-non-last succeeds, and a two-session/concurrent demotion test cannot leave zero managers. Fixes `05`/`12` HIGH.
- **T1.5 [BE] Security headers / middleware for `/workshop` + `/invite`.** App-wide block (or `src/middleware.ts`): enforce `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, and HSTS immediately; ship CSP as **Report-Only first**, then enforce after D-9's observation window. Proof: update `tests/vitest/landing-security-headers.test.ts` so `/workshop/:path*` and `/invite/:path*` are covered instead of explicitly absent; add response-header assertions on live dev routes; clickjacking frame test fails to render through the enforced anti-frame header even while CSP remains report-only. Fixes `05` HIGH. *(Coordinate with the Shared-Link plan's CSP-nonce work — memory.)*
- **T1.6 [BE] `/invite/.../accept` Origin check + enumeration copy.** Add Origin/same-site guard to `src/app/invite/[token]/accept/route.ts`; normalize invite success copy to remove the existing-vs-new oracle. Proof: cross-origin POST rejected; same-origin form from `src/app/invite/[token]/page.tsx` accepted; identical success message both paths. Fixes `05` LOWs.
- **T1.7 [QA] Runtime authz regression tests.** Replace source-snapshot-only assertions for collaboration actions with behavior tests: cross-project `copyProjectInviteLink` returns no invite data, unknown invite IDs do not reveal project existence, spoofed/unknown realtime identities render nothing, and restricted-sheet activity is invisible to project-only viewers.
