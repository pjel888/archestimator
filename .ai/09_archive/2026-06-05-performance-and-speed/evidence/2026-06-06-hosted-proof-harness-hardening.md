# Hosted auth/export proof harness hardening — 2026-06-06

Status: **LOCAL HARNESS/RUNTIME GUARDS IMPLEMENTED / SIGNED-OUT POST-DEPLOY PROOF CAPTURED / HOSTED SIGNED-IN AND EXPORT FIXTURES OPEN**.

## Why this was needed

The resumed UltraQA/team audit found local-fixable gaps in the hosted proof harnesses:

- `scripts/verify-hosted-export-route.ts` accepted `MARKDOWN_FILE` but called an undefined `writeMarkdown(...)` helper.
- Hosted export auth material could be sent to any configured `HOSTED_EXPORT_BASE_URL` without the auth harness' HTTPS/allowed-origin guard.
- Hosted export proof accepted workbook responses without requiring protected/private `Cache-Control` semantics.
- Hosted auth proof did not record cache-control/no-leak headers, so a redirect could look behaviorally correct while remaining unsafe to cache.

## Local changes

- Added sanitized Markdown proof output for hosted proposal export benchmark runs.
- Added `HOSTED_EXPORT_ALLOWED_ORIGINS` parsing and HTTPS/allowed-origin validation before sending hosted export auth material.
- Added private/no-store cache-control checks to hosted export samples and pass criteria.
- Added cache-control capture plus private/no-store pass criteria to hosted auth samples.
- Added `SENSITIVE_ROUTE_CACHE_CONTROL = "private, no-cache, no-store, max-age=0, must-revalidate"` to `src/proxy.ts` for protected/auth redirect responses generated by Proxy.
- Added focused regression coverage:
  - `tests/vitest/hosted-auth-route-smoke-script.test.ts`
  - `tests/vitest/hosted-export-route-smoke-script.test.ts`
  - `tests/vitest/proxy-sensitive-cache-headers.test.ts`
