# Beta Onboarding Flow Plan Pack

This pack is the implementation contract for an authenticated Archestimator
Workshop onboarding system. React Joyride v3 supplies short orientation and
contextual overlays; one versioned starter workspace pack supplies immediately
useful Projects, Estimate Sheets, Components, and Templates plus the deeper,
task-based Estimate Sheet practice needed for beta comprehension. A separate
manager-only Client links curriculum guides users through publishing, preview,
recipient, maintenance, and recovery work without crossing the public-share
trust boundary.

## Canonical Artifacts

- `IMPLEMENTATION_PLAN.md` — the one canonical execution order, decisions,
  assignment packets, ownership, evidence, recovery, and stop conditions.
- `01-CURRENT-STATE-AND-D1-AUDIT.md` — whole-application and active-D1 audit.
- `02-RESEARCH-AND-EXPERIENCE-SPEC.md` — external research and exact experience.
- `03-ARCHITECTURE-DATA-AND-VERIFICATION.md` — technical, persistence, security,
  accessibility, and evidence contracts.
- `04-ROUTE-AND-OVERLAY-INVENTORY.md` — exhaustive page disposition and modal
  integration ownership.
- `05-INDEPENDENT-REVIEW.md` — adversarial review and resolution record.
- `06-IMPLEMENTATION-AND-VERIFICATION-EVIDENCE.md` — final requirement audit,
  static validation, and explicit unrun-test/external-proof boundaries.
- `plan-pack.json` — machine-readable traceability manifest.

## Executive Direction

The implementation must not ship a single forced “grand tour.” It must combine:

1. one short, role-aware first-run orientation;
2. a four-task checklist completed by authoritative domain facts and activation
   events;
3. one curated starter workspace pack with three Projects, four Estimate
   Sheets, six Components, and three Templates;
4. one comprehensive, resumable Estimate Sheet learning path whose core
   completion requires user-performed price/save plus add/source actions and
   whose optional lessons cover hierarchy, row math, reusable structure,
   recovery, and independent transfer;
5. one manager-only Client links learning path that guides verified
   publication, scope/access review, copy or authenticated preview, recipients,
   status/maintenance, and safe recovery while keeping destructive actions
   optional;
6. durable resume, restart, replay, starter/tutorial recovery, and dismissal
   semantics;
7. a Settings surface named **Guidance & tours**; and
8. comprehension and transfer signals that distinguish generated
   starter/tutorial value from independent work.

React Joyride is the visual adapter. Existing product activation remains the
business source of truth. New instructional progress is stored separately at
user × workspace × flow × version scope. Activation producer source remains
unchanged; a separate non-forgeable origin distinguishes shared starter,
explicit per-user practice, and ordinary user-domain writes. Guided practice
is bound to one persisted tutorial version/generation. Seed events remain
auditable but never advance the real activation projection, and generation,
presence, route visits, opens, or receipts from an older copy can never mark
checklist/practice complete. Only the plan's closed successful
Blank/Duplicate/Template-derived creation and seven Estimate Sheet mutation
families are eligible user-domain checklist activity after authoritative
save/readback.

Beta v1 automatically installs a bounded, editable starter set into each new
eligible workspace. A per-user **Starter Examples** Project group contains the
shared residential Tutorial and a completed commercial Reference Project; an
editable **Sandbox — Quick Estimate** Project remains ungrouped so the Projects
page visibly teaches grouped and ungrouped organization. The shared workspace
also receives six starter Components split across two claimed custom folders
plus protected **Uncategorized** resolved/ensured by the existing Library
invariant without a starter folder claim, and three persisted starter
Templates organized by category. Starting Guided tutorial explicitly creates
one normal workspace practice Project for that user from the immutable
blueprint; joining editors never receive silent duplicate Projects. Every
starter asset is labeled, versioned, individually editable/archiveable, and
restorable only when inactive without overwriting surviving edits. This
includes deterministic rebinding of every eligible user's Tutorial/Reference
group memberships before a shared restore can report complete. This remains a
starter workspace, not an unbounded demo gallery or training academy.

Client links remain distinct from Proposals, Client Portals, and public
`/share/[token]` recipient sessions. The authenticated `/workshop/publisher`
guide may prepare and verify a normal manager action, but it never persists a
token/URL, drives the public route with Joyride, sends recipient email,
replaces a URL, or turns a link off without the user's explicit product action.
Core publish/share completion uses one short-lived in-memory server receipt so
the copy/Preview action must match the exact publication just verified in that
active run; the receipt and its binding digest are never stored or logged.

## Completion

All eight implementation units and fourteen acceptance criteria are complete
for local repository scope. The final evidence receipt is
`06-IMPLEMENTATION-AND-VERIFICATION-EVIDENCE.md`.

No automated product test, build, browser automation, screenshot, local or
remote D1 migration apply, deployment, or provider mutation was performed.
Those proof boundaries remain explicit `TEST_PROPOSAL` or release evidence,
not unfinished repository implementation.
