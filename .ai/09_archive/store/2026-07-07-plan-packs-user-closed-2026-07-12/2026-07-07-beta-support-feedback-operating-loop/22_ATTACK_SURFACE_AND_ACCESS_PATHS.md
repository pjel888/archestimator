# 22 — Attack Surface Inventory and Access-Path Matrix

Mandated structured artifacts (Improve-Plan-Prompt §6 API/Server-Action, §7 data). The Attack Surface Inventory covers every directly-reachable entry point; the Access-Path Matrix covers every planned data source.

## A. Attack Surface Inventory

Schema: `Entry point | Actor | Authn/authz and ownership check | Input validation | Output DTO | Cache/header behavior | Rate/abuse posture | Required tests`.

Server Actions are **directly-reachable POST endpoints** — each row below is reachable by a direct POST, so every row re-validates auth/authz server-side (no reliance on UI gating).

| Entry point | Actor | Authn/authz + ownership | Input validation | Output DTO | Cache/header behavior | Rate/abuse posture | Required tests |
|---|---|---|---|---|---|---|---|

**DTO minimization note:** `submitBetaFeedback*` return no data (redirect/inline-state only). The operator queue renders `message` + `user_email` into the DOM — this is intentional (triage needs the content) and gated to platform admins; it is the existing behavior, not new exposure. Reporter follow-up email sends `message` to the reporter's own address (within consent basis). Webhook payloads are **summary-only** (no `message`) — stricter than email because the webhook is a less-trusted sink.

**Rate/abuse posture summary:** no per-user rate limit at beta (T-09). Message length is bounded (4000 chars). The submit action is idempotency-weak (duplicate rows possible) — accepted at beta with client button-disable + PRG. P2 follow-up: Cloudflare WAF/rate-limit rule on the submit action.
