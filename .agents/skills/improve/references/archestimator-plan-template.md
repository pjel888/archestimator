# Archestimator Improve Plan Template

Use this template for improve-generated plans in Archestimator.

File naming:

```text
.ai/03_plans/<YYYY-MM-DD>-<topic-slug>/README.md
.ai/03_plans/<YYYY-MM-DD>-<topic-slug>/001-<slug>.md
```

Do not write root `plans/`.

## Plan File Template

```markdown
# Plan NNN: <imperative title>

> **Executor instructions:** Follow this plan step by step. Run every
> verification command and compare it to the expected result before moving on.
> Touch only in-scope files. If a STOP condition occurs, stop and report instead
> of improvising.
>
> **Drift check:** `git diff --stat <planned-at-sha>..HEAD -- <in-scope paths>`
> If any in-scope file changed since planning, compare the current-state excerpts
> below with live code before editing. A mismatch is a STOP condition unless the
> plan explicitly handles it.

## Status

- **Priority:** P0 | P1 | P2 | P3
- **Effort:** S | M | L
- **Risk:** LOW | MED | HIGH
- **Category:** bug | security | perf | tests | tech-debt | migration | dx | docs | direction
- **Depends on:** none | `NNN-<slug>.md`
- **Planned at:** commit `<short-sha>`, <YYYY-MM-DD>
- **Proof boundary:** local-only | provider-proven | manual-proof-pending
- **Owner gates:** none | <explicit approval/provider/legal/design gate>

## Why This Matters

Explain the user/product/engineering impact in 2-5 concrete sentences.

## Current State

- Relevant files and their roles.
- Short code or doc excerpts with `path:line` references.
- Applicable repo conventions from `AGENTS.md`, `.ai/00_system/*`,
  `.ai/10_state/*`, `.ai/03_plans/README.md`, and `DESIGN.md` when relevant.
- Existing verification commands and known baseline failures, if any.

## Scope

**In scope:**
- `path/to/file`

**Out of scope:**
- Provider mutation, deploys, package additions, migrations, or route families
  not explicitly approved.
- Any source file not listed above unless the plan tells the executor to stop
  and request plan revision.

## Implementation Steps

### Step 1: <imperative title>

Precise instruction with target files/symbols and expected code shape.

**Verify:** `<command>` -> expected result.

### Step 2: <imperative title>

Precise instruction.

**Verify:** `<command>` -> expected result.

## Test Plan

- New tests to add, with paths and cases.
- Existing tests to run.
- Browser/manual proof required for user-visible UI.
- Provider/manual proof explicitly separated from local-only checks.

## Done Criteria

- [ ] All implementation steps complete.
- [ ] Targeted tests pass.
- [ ] Type/lint/build checks pass where required by risk.
- [ ] UI or provider proof collected when the plan requires it.
- [ ] `.ai/10_state/*` or related canonical docs updated if project truth changed.
- [ ] No out-of-scope files modified.

## STOP Conditions

Stop and report if:

- Live files no longer match the current-state excerpts.
- The fix needs an out-of-scope file or provider action.
- A verification command fails twice after reasonable local fixes.
- A required approval, secret, fixture, or provider authority is missing.
- The plan conflicts with `AGENTS.md` or `.ai/00_system/*`.

## Maintenance Notes

- Review risks.
- Follow-up work intentionally deferred.
- Future changes likely to interact with this plan.
```

## Quality Bar

- A fresh executor can complete the work from the plan file alone.
- Every verification gate is command-based or explicitly manual/provider-bound.
- Scope boundaries are exact.
- STOP conditions are specific to the plan risks.
- No raw secrets or confidential data are copied into the plan.
- The plan lives under `.ai/03_plans`, not root `plans/`.
